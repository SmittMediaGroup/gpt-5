# Часть 4 — План внедрения для ночного агента

Дата: 2026-10-15. Для агента с доступом к коду GEO-Радара и серверу. Порядок — «первый рубль как можно раньше». Спецификация экранов, текстов и правил — в `03-продукт.md`; платёжка и право — в `02-рф.md`.

> [!warning] Что нужно от владельца ДО ночи 1 (без этого автомат не заработает)
> 1. Доступы/решение по платёжке: личный кабинет ЮKassa для ИП (или решение «начинаем с Robokassa/Prodamus» — сравнение в `02-рф.md`). Подключение магазина занимает 1–3 дня — подать заявку сегодня.
> 2. Реквизиты для оферты: ИНН/ОГРНИП, email поддержки.
> 3. SMTP/почтовый сервис для писем (достаточно одного транзакционного: Unisender Go / Notisend / RuSender — выбор в `02-рф.md`).
> 4. Подтверждение цен лестницы: 2 999 ₽ / 8 900 ₽ / 24 900 ₽мес (дефолты — `00-итог.md`, решение 2).

## Ночь 1 — продающий отчёт и приём денег (вручную, если платёжка ещё не одобрена)

Цель ночи: утром существующий бесплатный отчёт заканчивается кнопкой «Открыть весь план — 2 999 ₽», и этот путь способен принять деньги (хотя бы через выставленную ссылку на оплату).

- [ ] **1.1. Email в форме аудита сделать обязательным** + чекбокс согласия на ПДн со ссылками на политику и оферту. Страницы политики и оферты — по шаблонам из `02-рф.md` (черновики согласует владелец утром, но страницы должны существовать).
  Готово, когда: нельзя запустить аудит без валидного email и чекбокса; политика и оферта открываются.
- [ ] **1.2. Письмо «отчёт готов»** (T+0): после завершения прогона отправляется письмо с 3 цифрами и ссылкой на отчёт.
  Готово, когда: тестовый аудит → письмо в ящике, ссылка открывает отчёт.
- [ ] **1.3. Генератор PDF-плана v1.** Движок правил из `03-продукт.md` §3 (минимум: R1–R3, R6–R8, R10, R11, R18, R19 — правила, для которых данные уже есть в отчёте) + библиотека текстов §4 + шаблон HTML→PDF по структуре §2. Без дизайна-люкс: аккуратный одностилевой шаблон, яркий акцент, не чёрный.
  Готово, когда: по тестовому отчёту собирается PDF 15+ страниц, в котором диагноз — из данных отчёта, шаги — из сработавших правил, и нет ни одной запрещённой фразы из `metodika/audit-v2.md` §5 (прогнать автопроверкой по списку стоп-фраз).
- [ ] **1.4. Экран отчёта: блок плана.** Первые 2 шага полностью + остальные заголовками с замком + кнопка «Открыть весь план — 2 999 ₽» (тексты — `03-продукт.md` §6).
  Готово, когда: на свежем отчёте виден блок, заголовки шагов подставляются из данных этого отчёта.
- [ ] **1.5. Приём оплаты, временная схема.** Если ЮKassa ещё не одобрена: кнопка ведёт на форму «оставьте email — пришлём ссылку на оплату» + уведомление владельцу в Telegram; владелец шлёт ссылку из кабинета банка. Если одобрена — сразу виджет (см. 2.1).
  Готово, когда: клик по кнопке фиксируется в аналитике и приводит к письму/виджету.
- [ ] **1.6. Аналитика-минимум.** События: запуск аудита, отчёт открыт, клик по кнопке плана, оплата, скачивание PDF. Любой инструмент (Метрика + лог в БД).
  Готово, когда: тестовый проход виден в воронке событий.

## Ночь 2 — полный автомат оплаты и выдачи

- [ ] **2.1. ЮKassa: создание платежа из карточки отчёта** (сумма 2 999 ₽, метаданные: id отчёта, email), виджет/редирект на оплату.
  Готово, когда: тестовый платёж (тестовый магазин ЮKassa) проходит и возвращает на «спасибо».
- [ ] **2.2. Webhook `payment.succeeded`** → генерация PDF → запись заказа → страница «спасибо» с кнопкой скачивания → письмо с вечной токен-ссылкой (лимит 20 скачиваний).
  Готово, когда: оплата → PDF скачивается и письмо доходит без участия человека; повторный заход по ссылке работает.
- [ ] **2.3. Чек 54-ФЗ**: включить фискализацию в платёжке (решение по кассе — `02-рф.md`), позиция «Пошаговый план…», предмет расчёта «услуга/цифровой товар».
  Готово, когда: на тестовой оплате чек уходит на email покупателя.
- [ ] **2.4. Страница плана (экран 4)** с примером разворота (превью первой страницы PDF этого клиента) и FAQ.
  Готово, когда: страница открывается с кнопки в отчёте, в ней живые данные клиента.
- [ ] **2.5. Обработка краёв:** оплата при устаревшем отчёте (пересобрать), двойная оплата (вернуть/отдать ссылку), письмо не доставлено (кнопка «прислать ещё раз»), возврат по запросу (ручная кнопка у владельца).
  Готово, когда: по каждому кейсу есть тест или описанная ручная процедура.

## Ночь 3 — письма, консультация, поток

- [ ] **3.1. Серия писем** не-купившим (T+1, T+3, T+7, T+14) и купившим (T+2, T+10, T+30) — тексты из `03-продукт.md` §1; отписка в один клик.
  Готово, когда: тестовый контакт проходит серию с ускоренными таймерами; отписка работает.
- [ ] **3.2. Запись на консультацию 8 900 ₽:** страница с описанием + выбор слота (календарь или простая форма) + оплата той же платёжкой + письмо подтверждения с ссылкой на видеозвонок.
  Готово, когда: тестовая запись и оплата проходят, слот виден владельцу.
- [ ] **3.3. «Спасибо»-апселл и последняя страница PDF** ссылаются на запись (QR/ссылка).
  Готово, когда: ссылки ведут на работающую страницу записи.
- [ ] **3.4. Поток: включить каналы нулевого бюджета.** Опубликовать подготовленный кворк (`prodazhi/kwork-geo.md` — проверить лимиты формы) со ссылкой-воронкой на бесплатный аудит в сценарии сдачи; выпуск «барометра» (`barometr/`) со ссылкой «проверьте свой бренд бесплатно».
  Готово, когда: кворк на модерации/опубликован; выпуск барометра со ссылкой опубликован.
- [ ] **3.5. Дашборд воронки для владельца:** страница/таблица с числами по дням: аудиты, отчёты, клики, оплаты, выручка, письма.
  Готово, когда: владелец видит вчерашние цифры без запроса к агенту.
