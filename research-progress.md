## Блок 6. Что я упускаю: пять слабых мест продукта, 25.09.2026

Пишу прямо. Каждое слабое место опирается на файлы этой ветки.

### 1. «Ноль в YandexGPT и GigaChat» — не находка, а артефакт замера
Через API опрашивается голая модель без веб-поиска. Пользователь видит другое: Алису в поиске и GigaChat в приложении, где поиск подключён.
- Completion-эндпоинт YandexGPT не ходит в поиск (`metodika/chistaya-sessiya.md`, proto yandex-cloud/cloudapi).
- В API GigaChat есть встроенный инструмент `web_search`, но он включается отдельно (`research-mehanika/01-istochniki.md`, SDK ai-forever/gigachat).
- Ноль означает только одно: модель не помнит мелкие иркутские компании. Для локального бизнеса это ожидаемо и ничего не говорит о том, «как видит Сбер».

Фраза «в Яндексе и Сбере бизнес видят иначе» на этих данных верна только наполовину. Про Яндекс данные есть: Алиса против ChatGPT. Про Сбер данных нет.

**Исправление:**
- GigaChat опрашивать с `web_search`.
- Для Яндекса взять генеративный ответ Search API (`/v2/gen/search`) или ручной протокол Алисы.
- Голые модели оставить отдельной строкой «память модели», и ставить её не рядом с поисковыми поверхностями.

### 2. Главная продающая находка (+51 / +22 / −20 п.п.) пока не подтверждена статистикой
В исходных данных нет n.
- По расчёту `barometr/vypusk-1.md` разница 43% против 26% значима только начиная примерно с 62 независимых ответов на систему. При двух повторах на промпт нужно около 93 ответов. При n = 30 это шум (p = 0,18).
- Разница 17% против 15% незначима при любом реалистичном объёме.
- Есть и эффект выбора. Из многих пар «компания × система» показаны самые большие разрывы. Самая крайняя из многих случайных разниц всегда выглядит внушительно, и без поправки на множественные сравнения (Холм, `metodika/audit-v2.md`) это завышение.
- Одна дата и семь компаний в двух странах — это пилот, а не закономерность.

**Исправление:** пересчитать каждую из трёх цифр с n, интервалом Ньюкомба и поправкой Холма. Публиковать только то, что пройдёт проверку. До этого называть их «предварительными наблюдениями».

### 3. Непонятно, что именно я называю «Поиском с Алисой»
У потребительской Алисы публичного API нет (`metodika/chistaya-sessiya.md`, `metodika/audit-v2.md`). Есть три варианта снятия, и все с проблемами:
- **Браузерная автоматизация.** Может нарушать соглашение Яндекса. На ответ влияют регион, cookies и память: с лета 2026 у Алисы есть память о прошлых диалогах.
- **Генеративный ответ Search API.** Это другая поверхность: по документации ответ строится по заданным сайтам, до 5 штук.
- **Ручной прогон.** Даёт мало ответов.

Если в отчёте написано «Поиск с Алисой» без уточнения способа, клиент, который проверит сам и увидит другое, перестанет доверять всему отчёту.

**Исправление:** в отчёте всегда показывать блок «Условия замера» по шаблону из `chistaya-sessiya.md`. Один раз сравнить `/v2/gen/search` с живой Алисой на 20 запросах.

### 4. Повторный замер через 7–14 дней обещает то, чего почти никогда не покажет
- При пакете 19 900 ₽ минимальная различимая разница составляет +17–21 п.п. от 10% (`metodika/audit-v2.md`).
- Изменения на сайте доходят до ответов не сразу. Смена robots.txt у Яндекса срабатывает за 2–14 дней. А главный фактор — позиция в топ-10 Яндекса, из которого приходит ~90% источников Алисы (`research-mehanika/ИТОГ.md`). Эта позиция за две недели почти не меняется.
- Типичный итог повторного замера: «изменений в пределах погрешности». Для клиента это звучит как «ничего не сработало».
- Кроме того, эта функция не уникальна: у Брендометра есть повторные замеры после публикаций (`research-rynok/02-instrumenty.md`).

**Исправление:**
- В аудите повторный замер делать как проверку устойчивости: тот же набор запросов, контроль шума, A/A-тест.
- Замер эффекта правок перенести на 4–8 недель и продавать в сопровождении.
- Заранее, в самом оффере, писать, какую разницу замер способен увидеть.

### 5. Аудит измеряет симптом и пропускает главный рычаг и главную дешёвую находку
Попадание в Алису определяется в первую очередь позицией в Яндексе и данными в картах и агрегаторах (`research-mehanika/06-cheklist.md`, пункты 1–10). Метрика «доля упоминаний» этого не объясняет.

Сейчас в продукте нет трёх вещей:

- проверки, есть ли целевые страницы в топ-10 Яндекса;
- разбора, какие агрегаторы стоят в источниках ответа.

Отсюда рыночная проблема. Из трёх заявленных отличий два не уникальны: интервал есть у Брендометра, проверка фактов — у Getllmspy, Lead.Media и Torkunoff (`research-rynok/ИТОГ.md`). При этом бесплатный вход (мини-аудит) дают как минимум пять агентств, а у меня его нет.

**Исправление:**
- Добавить в аудит нулевой шаг, топ-10 и источники ответа.
- Сделать бесплатный срез: нулевой шаг плюс 5–10 запросов.
- Отличия переформулировать честно: «Алиса и российские ИИ с поиском, Иркутск, методика с погрешностью».
