# Ошеломляющий лендинг: регламент

Цель — страница, от которой у заказчика «вау», и при этом она лёгкая, читаемая и
не выглядит дёшево. Стек жёсткий: **Vite + React + Tailwind + Framer Motion + Lenis**.
Тяжёлое 3D (three.js, R3F, Unity) не берём.

Работа идёт по шагам. После шагов 1, 3 и 6 — остановка и показ результата.

## Шаг 0. Понять, что продаём

Один абзац: кто клиент, что покупает, какое одно действие должен сделать посетитель.
Если этого нет — всё остальное бессмысленно, страница будет красивой пустышкой.

Выбрать **один главный предмет** — то, что будет в герое крупно. Не коллаж, не
«атмосфера», а один предмет (букет, банка, флакон, блюдо).

## Шаг 1. Палитра и типографика — до вёрстки

1. Взять готовую связку из `dannye/palitry.md` или собрать свою по правилу:
   **1 насыщенный акцент + 1 светлый нейтральный + 1 тёмный для текста**, плюс
   максимум один дополнительный цвет. Четыре насыщенных цвета — это уже «конструктор».
2. Записать палитру токенами в `index.css` через `@theme`, цвета — в `oklch()`,
   чтобы шкала строилась по светлоте.
3. Доля цветного: **насыщенный цвет занимает 15–30% площади первого экрана**,
   остальное — светлый нейтральный и воздух. Не наоборот.
4. Пара гарнитур: одна для заголовков (характерная), одна для текста (нейтральная).
   Готовые пары — `dannye/tipografika.md`.
5. Кегль героя: **9–12% ширины экрана** на десктопе (на 1440 px это 130–175 px),
   на телефоне 9–12 vw. Для длинной русской фразы — 5–6%. Меньше 4% — заголовок
   не «кричит», и эффекта не будет. Замеры двух выборок — `dannye/tipografika.md`.

СТОП. Показать владельцу палитру и заголовок — два скриншота, не больше.

## Шаг 2. Медиа

1. Промты брать из `promty/`, **начиная с `01-yarkiy-svet.md`** — там список слов,
   из-за которых кадры выходят тёмными.
2. Сначала картинка (2–2,5 кредита), видео — только из одобренной картинки (16 кредитов).
3. Каждый кадр перед вёрсткой прогнать через `python dannye/zamer.py kadr.png`.
   Пороги для героя: красочность ≥40, светлота L* 45–70, яркий цвет ≥12% площади,
   тёмное <25%, выбито в 255 <1%. Не прошло — не верстаем, перегенерируем.
4. Скриншоты сайтов и интерфейсов в генерацию не отправлять никогда — модель ломает текст.

## Шаг 3. Каркас: 6 экранов, не больше

| Экран | Что в нём |
|---|---|
| герой | предмет крупно + заголовок 8–14% ширины + одна кнопка |
| «боль → обещание» | крупная фраза на цветной плашке, без картинок |
| продукт/услуга | 3–5 карточек с короткими петлями или фото |
| как это работает | 3 шага, цифры крупно |
| доверие | цена, отзыв, факт |
| действие | форма или одна кнопка |

Больше шести экранов — лендинг превращается в сайт, и «вау» рассыпается.

СТОП. Показать каркас без анимаций: если страница не работает статичной, анимация её не спасёт.

## Шаг 4. Движение

Значения — из `dannye/dvizhenie.md`, не подбирать на глаз.

**Главное правило, оно же против «ИИ-штампа».** Официальный скилл Anthropic
`frontend-design` прямо называет признаком сгенерированной страницы
«fade-and-slide-up entrances on each section and hover transitions on every card»
и требует обратного: «A single orchestrated moment — one page-load sequence or one
reveal — lands better than scattered effects»
(https://github.com/anthropics/skills/tree/main/skills/frontend-design).
То же в кукбуке Anthropic: «one well-orchestrated page load with staggered reveals
creates more delight than scattered micro-interactions»
(https://platform.claude.com/cookbook/coding-prompting-for-frontend-aesthetics).

Поэтому минимум такой:
1. **Один срежиссированный момент** — вход первого экрана: заголовок по словам,
   предмет, кнопка; stagger 0,06–0,10 с, вся сцена укладывается в 1,2 с.
2. **Один эффект на прокрутке на всю страницу** — либо параллакс героя
   (`useScroll` + `useTransform` + `useSpring`, сдвиг ≤15% высоты), либо одна
   sticky-секция 150–250vh со скрабом. **Один, не три.**
3. **Отклик на наведение** — только у кнопок и там, где это сообщает о
   кликабельности; не на каждой карточке подряд.
4. Остальные секции появляются без анимации или с простым изменением
   непрозрачности. Это осознанный выбор, а не экономия.

Запрещено: анимировать `width/height/top/left/box-shadow`; держать больше двух
одновременных анимаций в поле зрения; анимация первого экрана дольше 1,2 с.

**Отдельно про reduced-motion:** у Motion `<MotionConfig reducedMotion>` по
умолчанию `"never"` — библиотека системную настройку НЕ уважает, пока не поставить
`"user"` явно (https://motion.dev/docs/react-motion-config). Ставим в корне приложения.

## Шаг 5. Телефон

1. Герой-видео на телефоне заменяется постером или облегчённым файлом (≤600 КБ).
2. Скраб-секции на телефоне упрощаются или отключаются — на тач-устройствах
   скраб даёт рывки.
3. Проверить горизонтальный перелёт: `document.documentElement.scrollWidth - clientWidth`
   должно быть 0 при ширине 390.
4. `prefers-reduced-motion: reduce` — через `useReducedMotion`: гасим параллакс,
   скраб, автозапуск, петли; оставляем только непрозрачность ≤0,2 с.

## Шаг 6. Замер перед сдачей

```bash
NODE_PATH=... node dannye/zond-sayta.cjs urls.txt shots out.json
CVET_OUT=itog.json python dannye/zamer.py shots/
```

| Показатель | Порог |
|---|---|
| красочность первого экрана | ≥40 |
| доля яркого цвета | 12–30% |
| доля тёмного (V<0,25) | <25% |
| вес первого экрана | ≤1,5 МБ, из них видео ≤600 КБ |
| LCP на 4G | ≤2,5 с |
| горизонтальный перелёт на 390 px | 0 |
| контраст текста к фону | ≥4,5:1 (крупный ≥3:1) |

СТОП. Показать владельцу: два снимка (десктоп, телефон) + таблицу замеров.

## Шаг 7. Сдача

1. Бэкап текущей версии перед любой правкой боевой страницы — папка `backups/ГГГГ-ММ-ДД/`.
2. Ничего не публикуется без явного «ок» владельца.
3. Строка в журнал `C:\ControlCenter\Журнал\<дата>.md`.

## Частые ошибки (проверено на себе)

| Ошибка | Чем кончается |
|---|---|
| «кинематографичный» герой | красочность 23 вместо 40, владелец говорит «полумрак» |
| лечить тёмный кадр грейдингом | светлота растёт, цвет не появляется — нужен другой исходник |
| четыре насыщенных цвета | страница выглядит как детский конструктор |
| три скраб-эффекта подряд | никто не досматривает, вес 8 МБ |
| `mix-blend-mode: screen` на светлом фоне | секция забеливается целиком |
| текст поверх фотографии без подложки | контраст 2:1, не читается на телефоне |
