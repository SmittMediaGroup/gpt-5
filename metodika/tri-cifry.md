# Три главные цифры: +51 / +22 / −20 п.п. — пересчёт с n и интервалами

**Дата: 25.09.2026.** Задача (решение владельца в PR): пересчитать разницы долей упоминаний «Поиск с Алисой» − ChatGPT по прогону 25.09.2026 с числом ответов n и интервалами Уилсона; где разница не значима — так и написать.

## Главное: точный пересчёт сейчас невозможен — сырых чисел нет
В ветке и в брифе есть только итоговые разницы в п.п. Нет ни одного из нужных чисел: сколько ответов собрано по каждой системе (n) и в скольких из них назван бренд (k). Без k и n интервал Уилсона не считается — это не округление, а отсутствие данных. **Поэтому ни одну из трёх цифр я пока не называю значимой.** Статус всех трёх: «предварительное наблюдение, n не указано».

Что сделано вместо этого:
1. Посчитано, **при каком n** каждая разница стала бы значимой (таблица ниже) — это показывает, какие из трёх цифр имеют шанс выдержать проверку.
2. Написан скрипт `metodika/tri_cifry.py`: подставляете k и n из журнала прогона — получаете Уилсон для каждой доли, интервал Ньюкомба для разности и вердикт «значима / не значима».

## Пороговая таблица
Разница считается значимой, если 95 % интервал Ньюкомба для разности долей не содержит 0 (правило из `metodika/audit-v2.md`; пересечение интервалов Уилсона как критерий не используется). n — ответов на **каждую** систему по этой компании. ## Что это значит для каждой цифры
- **+51 п.п. (прокат авто).** Разница такого размера становится значимой уже при ~7–15 ответах на систему. Если в прогоне было хотя бы 15 ответов на систему по этой компании — почти наверняка значима. **Вердикт: вероятно значима, но подтвердить можно только по k/n.**
- **+22 п.п. (строительство домов).** Нужно ~23–40 независимых ответов на систему, а при повторах промптов — 35–79. **Вердикт: неизвестно.** Если в прогоне было меньше ~40 ответов на систему — не значима.
- **−20 п.п. (питомник растений).** Нужно ~27–48 независимых ответов, при повторах — 40–96. **Вердикт: неизвестно;** при типичном пилоте (десятки ответов) скорее не значима.

## Две поправки, которые ухудшают картину
1. **Множественные сравнения.** Три цифры выбраны как самые крупные из сравнений по семи компаниям. Самая крупная из многих случайных разниц всегда выглядит внушительно. При поправке Холма на 7 сравнений самая сильная разница проверяется на уровне 0,05/7 ≈ 0,007 — пороги n для неё растут примерно в 1,5–1,7 раза. Для +51 это не критично, для +22 и −20 — критично.
2. **Одна дата.** Даже значимая разница описывает один день. Устойчивость проверяется повторным прогоном по тому же протоколу (A/A-тест, `metodika/chistaya-sessiya.md`).

## Пример работы скрипта (цифры условные, не из прогона)
```
$ python3 metodika/tri_cifry.py 13 30 5 30 1.5
Алиса: 13/30 = 43.3%  [95 % Уилсон: 27.4% – 60.8%]
ChatGPT: 5/30 = 16.7%  [95 % Уилсон: 7.3% – 33.6%]
Разность: +26.7 п.п.  [Ньюкомб, DEFF=1.5: -1.7 … +50.2]
НЕ ЗНАЧИМА: интервал разности содержит 0
```
Разница +26,7 п.п. при 30 ответах на систему с повторами промптов — **не значима**. Так выглядит типичная «эффектная» цифра на малой выборке.

## Как пересчитать по-настоящему (15 минут)
1. Из журнала прогона 25.09.2026 (`runs.jsonl` или таблица) выписать по каждой из трёх компаний: n ответов Алисы, k упоминаний у Алисы, n и k у ChatGPT, число повторов на промпт.
2. Запустить `python3 metodika/tri_cifry.py k_алиса n_алиса k_chatgpt n_chatgpt DEFF` (DEFF = 1 без повторов, 1,5 при двух, 2,0 при трёх).
3. В оффер и лендинг переносить только значимые разницы, с интервалом и n. Незначимые — формулировкой «разница в пределах погрешности».
